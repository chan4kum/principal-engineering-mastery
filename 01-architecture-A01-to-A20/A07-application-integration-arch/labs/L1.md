# L1 · Synchronous vs async

From the repository root:

```sh
uv run --locked --extra api pytest -q tests/test_a07_projects.py -k guided
```

Predict the effect of a downstream inventory outage on both submit paths. The synchronous API returns 503, while queued admission returns 202 and a status URL. The subprocess commits the effect, exits with status 75 before acknowledgment, and leaves the job pending. A fresh worker replays it, marks the job done, and leaves one effect. The worker is a sequential local fixture. Production must separately bound leases, retries and concurrent ownership.

Predict the response or state before running. Record normal, broken and recovered evidence and name the boundary that controls the outcome. Scratch variants and pytest data can be discarded after recording evidence. The Redis container is private and self-removing.
