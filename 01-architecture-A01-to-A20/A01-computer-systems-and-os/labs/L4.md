# L4 · Thread safety

Two threads update one count. Predict each load and store with and without the lock.

```sh
EXP=01-architecture-A01-to-A20/A01-computer-systems-and-os/examples
uv run python "$EXP/A01.25.py" --break
uv run python "$EXP/A01.25.py"
```

In the failure case the barrier forces both reads before either write. The count ends at 1. Inspect which value became stale. In the repaired case the lock covers the whole read–modify–write and the count ends at 2. Run both variants ten times. Try starting from 7, then implement per-worker results and aggregate them. Record which design actually shares mutable state and where it synchronizes.

When diagnosing a reproduction, keep the barrier out of the locked section so one participant does not wait for another that cannot enter. The barrier has a timeout and the pool closes on exit. Remove scratch copies.
