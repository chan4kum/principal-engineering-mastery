# L2 · CPU versus I/O

Predict which case has elapsed time much greater than CPU time. Sleep is a controllable stand-in for blocked I/O.

```sh
LAB=01-architecture-A01-to-A20/A01-computer-systems-and-os/labs
uv run python "$LAB/cpu_io.py" wait
uv run python "$LAB/cpu_io.py" cpu
docker run --rm --network none --cpus=1 -v "$PWD/$LAB:/lab:ro" python:3.12-slim python /lab/cpu_io.py cpu
docker run --rm --network none --cpus=0.25 -v "$PWD/$LAB:/lab:ro" python:3.12-slim python /lab/cpu_io.py cpu
```

Compare the identical CPU task inside both containers. Under cgroup v2, look for `nr_throttled` and `throttled_usec` deltas and higher wall time in the constrained run. A short job may fit a period. If counters do not change, increase the bounded loop length in a scratch copy and repeat. Also run the wait case under the constrained setting and test whether the wait alone consumes the quota.

Restore the one-CPU control and report wall seconds, CPU seconds and throttling deltas. Low process CPU alone can indicate parking, contention or quota. A request timeline is needed to distinguish them. Containers self-remove. Remove your scratch copy.
