## 1. The problem & why it exists

A service cannot read a config file even though the machine has already booted. Separate system bootstrap from application startup. Diagnose config access using the application error and permissions first.

## 3. Step-by-step mechanism & minimal dry-run

Firmware and a loader start the kernel. The kernel initializes resources and launches user space. A running application invokes syscalls under its own credentials.

**Trace.** Boot loader -> kernel -> init -> application -> open config -> success or ENOENT.

**Boundary case.** A missing config introduced after boot only affects that application path. Surface the missing filename and retry after provisioning it.

## 4. Formal rigor & quantitative math

With sequential startup phases of durations a, b, c, total is a+b+c. At 0.5 s, 1.8 s and 0.7 s, service can start at 3.0 s.

## 7. Production & multi-cloud bridge

A Kubernetes readiness failure can occur long after the node kernel booted. Check pod events separately from node lifecycle on EKS, AKS and GKE.
