## Inventory and scan a pinned image

Run the [Docker exercise](supply-chain.sh) against the pinned public Python image. Docker retrieves the image and pinned Anchore tool images if absent. Grype needs access to its vulnerability database. The exercise exports the image without running it, inventories the archive with networking disabled, and scans the resulting SBOM. Findings depend on the platform image and database date.

```sh
bash 01-architecture-A01-to-A20/A15-security-privacy-global-scale/labs/supply-chain.sh
```

Record the repository digest, component count, scanner database metadata and finding severity from the evidence directory. Review candidate findings in context with advisory and package evidence. A report, an SBOM and a trusted build attestation answer different questions. The local release-policy mutation above gives a deterministic hold without adding a vulnerable production dependency.

Use `--inventory-only` to exercise inventory when the scanner database is unavailable. Retain the output directory while reviewing evidence, then remove it when finished.

To scan inventory already generated on disk, install [Grype](https://oss.anchore.com/docs/installation/grype/) and run the same script with `--scan-existing /path/to/evidence`. This path uses the local scanner and its configured database.
