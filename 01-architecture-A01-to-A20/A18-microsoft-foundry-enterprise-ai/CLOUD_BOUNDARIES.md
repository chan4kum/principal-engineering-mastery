# Comparing AWS, Azure and Google Cloud implementations

Start from the invariant and failure evidence in the linked phase. Vendor services supply pieces of the architecture. A tenant policy, release gate and evidence-retention policy still need an owner and acceptance tests.

| Design constraint | AWS | Azure | Google Cloud | Evidence to collect |
| --- | --- | --- | --- | --- |
| Versioned model rollout | [SageMaker inference deployment](https://docs.aws.amazon.com/sagemaker/latest/dg/deployment-guardrails.html) | [Azure Machine Learning managed online endpoints](https://learn.microsoft.com/en-us/azure/machine-learning/how-to-safely-rollout-online-endpoints) | [Vertex AI deployment](https://docs.cloud.google.com/vertex-ai/docs/predictions/deploy-model-api) | [A14](../A14-advanced-llmops-evals-safety/README.md). Immutable model and test identities, identical cohorts, measured rollback and current routing. |
| Workload identity and rotation | [AWS IAM](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html) | [Managed identities](https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/overview) | [Workload Identity Federation](https://docs.cloud.google.com/iam/docs/workload-identity-federation) | [A15](../A15-security-privacy-global-scale/README.md). Separate identity, resource grant, supported reachability and retired credential behavior. |
| Tenant-scoped retrieval | [Amazon OpenSearch fine-grained access](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/fgac.html) | [Multitenancy with Azure AI Search](https://learn.microsoft.com/en-us/azure/search/search-modeling-multitenant-saas-applications) | [Vertex AI Vector Search filtering](https://docs.cloud.google.com/vertex-ai/docs/vector-search/filtering) | [A18](README.md). Verify trusted tenant identity-to-scope flow. Metadata filters alone do not authenticate a caller. Test caches, permission change and fallback. |
| Transaction-critical write | [Amazon RDS for PostgreSQL](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/CHAP_PostgreSQL.html) | [Azure Database for PostgreSQL](https://learn.microsoft.com/en-us/azure/postgresql/flexible-server/overview) | [Cloud SQL for PostgreSQL](https://docs.cloud.google.com/sql/docs/postgres/introduction) | [A16](../A16-system-design-and-interviews/README.md). Confirm unique committed effect under concurrent writes, retry identity and cross-region writer policy. |
| Audit evidence | [AWS CloudTrail](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-user-guide.html) | [Azure Activity log](https://learn.microsoft.com/en-us/azure/azure-monitor/essentials/activity-log) | [Cloud Audit Logs](https://docs.cloud.google.com/logging/docs/audit) | [A17](../A17-regulated-ai-compliance-governance/README.md). Explain what the infrastructure log covers, then independently prove application reviewer authority and exact request identity. |
| Edge deployment lifecycle | [AWS IoT Greengrass](https://docs.aws.amazon.com/greengrass/v2/developerguide/how-it-works.html) | [Azure IoT Edge](https://learn.microsoft.com/en-us/azure/iot-edge/about-iot-edge) | [Google Distributed Cloud connected](https://docs.cloud.google.com/distributed-cloud/connected/latest/docs/overview) | [A19](../A19-voice-multimodal-edge-embedded-ai/README.md). Compare deployment targets and constraints. Validate offline behavior and supported update signatures on the selected hardware. |
| Customer delivery | [AWS Well-Architected](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) | [Azure Well-Architected](https://learn.microsoft.com/en-us/azure/well-architected/) | [Google Cloud Well-Architected](https://docs.cloud.google.com/architecture/framework) | [A20](../A20-forward-deployed-product-leadership/README.md). Identify each organization's rollout authority, diagnostic access and restoration criteria. |

In the local exercises, keep price, traffic and residency inputs synthetic. In an actual design review, verify region, deployment type, supported features, quotas, network topology and contract terms before treating any of these services as equivalent.
