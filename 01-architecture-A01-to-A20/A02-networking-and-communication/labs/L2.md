# L2 · TLS chain

```sh
LAB=01-architecture-A01-to-A20/A02-networking-and-communication/labs
bash "$LAB/run.sh" L2
```

In a disposable client container, OpenSSL creates a temporary self-signed test root, a one-day leaf with SAN `service.test`, and a loopback TLS service. The key files and test trust root are deleted on exit.

1. Predict what changes when the same certificate is presented to a client without the root CA, with the right CA and wrong hostname, and with the correct CA and hostname.
2. Observe `openssl s_client` fail the first two handshakes under `-verify_return_error`. Read the verification messages. A matching name alone cannot make an untrusted chain succeed.
3. Repair by specifying the generated CA file and expecting `service.test`. Verify the peer subject, issuer, and return code 0.
4. Extend the lab by generating another leaf under the same CA with a different SAN. Keep the client verification switches in place.

The root and endpoint never leave the container. See [TLS commands](tls.sh) and [phase index](../README.md).
