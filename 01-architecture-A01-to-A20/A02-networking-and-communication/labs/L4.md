# L4 · Proxy timeouts

```sh
LAB=01-architecture-A01-to-A20/A02-networking-and-communication/labs
bash "$LAB/run.sh" L4
```

```text
curl -> NGINX -> FastAPI yields 'first', waits 700 ms, yields 'last'
```

1. Predict the output of `/stream` with a 3 s upstream read inactivity limit and buffering disabled.
2. Call `/broken` with a 200 ms read limit. The first chunk should arrive, followed by an interrupted response. Once headers have been forwarded, the proxy cannot replace the original status with a fresh 504 on the same response.
3. Return to `/stream` and verify both chunks and a clean client exit. Record the limits and compare client bytes with proxy logs.
4. For a buffering variant, start the three L4 services using `docker compose -p pem-a02-stream up -d routed-api proxy proxy-client` in the lab directory after running the script. Compare `/buffered` and `/stream` from `proxy-client` using `curl -N --trace-time --trace-ascii -`. Buffer release depends on actual proxy framing, flush behavior, and response length. Save observed timings before drawing a conclusion. Run `docker compose -p pem-a02-stream down` when finished.
