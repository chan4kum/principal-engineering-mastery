# L3 · NAT and routing

```sh
LAB=01-architecture-A01-to-A20/A02-networking-and-communication/labs
bash "$LAB/run.sh" L3
```

```text
client 172.31.241.10 -> gateway .241.2 | .242.2 -> API 172.31.242.10:8000
```

The client and gateway have namespace-local network administration for this lab. The gateway only forwards in isolated Docker networks. No host networking or published ports are used.

1. Predict which route `ip route get` will pick. The script adds one specific route to the backend subnet via the gateway's frontend address.
2. Observe that `/peer` sees source 172.31.242.2 when the gateway applies SNAT. The directly connected backend can return traffic to that address.
3. Delete only the scoped SNAT rule. Predict why the API cannot send a reply to the original source without a return route and observe a bounded curl failure. Restore the same rule and check the returned address.
4. For a variant on a disposable copy, replace translation with an explicit return route via the gateway by granting only the backend container the required capability. Compare peer addresses and verify no rules persist after teardown.

The runner removes containers and both networks. If those ranges overlap local Docker usage, choose two unused ranges and update addresses in the runner and Compose file together. [Phase index](../README.md)
