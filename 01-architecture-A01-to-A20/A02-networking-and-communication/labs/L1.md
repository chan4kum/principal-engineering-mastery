# L1 · Packet path

Run from the repository root with Docker Compose v2.

```sh
LAB=01-architecture-A01-to-A20/A02-networking-and-communication/labs
bash "$LAB/run.sh" L1
```

The lab starts a FastAPI service and a client on an internal container network with no published ports. Image preparation may fetch public package dependencies. All capture is from the disposable client.

1. Predict the DNS answer source and endpoint port. `dig api A` queries Docker's embedded resolver; the answer maps the service name to its container interface.
2. Inject the failure by querying the reserved nonexistent name `wrong-name.invalid`. Observe the missing A record. Resolver status can depend on the host's upstream configuration.
3. Repair by using `api` again. In the verbose curl output, match DNS-derived address, connect and HTTP 200. Inspect the `ss` snapshot and the bounded capture's SYN and SYN-ACK.
4. Save the DNS question, peer tuple and capture timestamps. Compare a capture started before a fresh request with one started after. Explain why an absent packet can reflect capture timing.

The runner automatically removes its containers and networks. It leaves reusable lab images. See [packet probe](packet.sh) and [phase index](../README.md).
